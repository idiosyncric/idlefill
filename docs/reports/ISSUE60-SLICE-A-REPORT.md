## A1 — feed-off providers (code)

`IdleDetector` treated a missing/failed activity feed as DEGRADED, and a
degraded signal can never be idle — so key-gated engines with no feed
(oMLX: `/api/metrics/activity` → 404) were permanently unwatchable. Fix:
an explicit empty `activity_path` is a DECLARATION of "no feed". The
detector then disables the feed signal (no fetch attempted), and
`log_glob` mtime alone carries the verdict. Fail-closed posture is
unchanged: a glob that matches nothing yields `idle_for_s: null` → never
idle. `feed_enabled` rides the signal and the dashboard (ADD key, the
state-shape contract). Config/arbiter/API all honor an explicit `""`
while an absent key keeps the llama-swap default. New suite
`server/test/feed-off.test.ts` (7 tests).

## B (pulled in by owner) — per-server API keys

Owner asked "shouldn't the inference servers allow me to add API keys?"
— the locked brief files exactly this as the Slice B credential item.
Implemented:

- `ServerConnection.auth_token` — credential on the ROW; the real
  fetcher sends `Authorization: Bearer <token>` on feed fetches when set;
  the watched row seeds from config `server_auth_token`.
- WRITE-ONLY contract: `/api/state` (authenticated AND anonymous),
  `/api/servers`, and the POST response STRIP the field and carry
  `auth_set` (boolean) instead. Mesh snapshots were already name+signal
  only. Proven live: the token value never appears in any response body.
- Patch semantics: non-empty sets, `""` is the clear sentinel, absent
  keeps the stored value (round-trips can never drop the secret).
- `StateStore.save` now writes 0600 (mode forced on the tmp before the
  rename) — the state file is the only place the value lives.
- Dashboard: password row on add + edit forms (empty=keep, type=replace,
  remove tick box=clear sentinel); "API key | set (hidden)" exception row.
- `idlefill-control`: `--auth TOKEN` on add/set, `--auth-clear`, `key:set`
  in the listing.
- 9 tests (`server/test/server-key.test.ts`) + the full live story on the
  running arbiter against a key-gated probe engine: keyed row →
  `degraded:false idle:true idle_for_s:407` on a feed that 401s without
  the key; clear sentinel → degraded (fail-closed); re-set → healthy.
- Gates: server 144, client 83, adapters 19 pass; tsc (server+client) and
  build clean.
